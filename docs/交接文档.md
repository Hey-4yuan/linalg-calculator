## 0. 三十秒版本

一个**纯前端**的线性代数计算器。计算全在浏览器，用精确分数（不是浮点）；唯一的外发请求是用户自己配的 OCR 视觉模型接口。

## 2. 技术栈实情

| 层 | 实际使用 | 备注 |
|---|---|---|
| UI | React 19.2.4（装的是 19.2.8） | 函数组件 + hooks，无全局 store |
| 路由 | react-router-dom 7.13.2，`BrowserRouter` | basename 由 `resolveBasename()` 推断 |
| 样式 | Tailwind CSS 4.2.2 + CSS 变量 | 类名走 v4 语法 |
| 组件原语 | Radix UI（27 个包）+ 自封装 shadcn 风格 | 只用 Dialog/Switch/Tabs/Toast 等少数 |
| 构建 | Vite 8（rolldown 内核） | `vite build --emptyOutDir` |
| 平台库 | `@lark-apaas/client-toolkit-lite` 1.1.33 | `scopedStorage`、logger、AppContainer；`__miaoda_<appId>__:` 前缀是它加的 |
| 原生壳 | Capacitor 6 | 包名 `com.doubao.linalg`，仅 INTERNET 权限 |
| 测试 | 自建断言 + esbuild 打包 | 没有 Vitest/Jest |

### 一个容易误判的点

`package.json` 里有 40 多个运行时依赖（echarts、embla-carousel、react-day-picker、react-hook-form…），**绝大多数是脚手架预设带的，业务代码没用**。实际用到的只有 react / react-dom / react-router-dom / radix 少数几个 / lucide-react / tailwind 系 / lark toolkit。

→ 想瘦身可以删，但**先跑一遍 `npm run build:all` 再打开页面点一圈**，别只信 import 扫描。安装体量约 874 个包、几分钟，主要成本在这里。

## 5. 关键设计决策（以及被否掉的方案）

| 决策 | 选了什么 | 否掉了什么，为什么 |
|---|---|---|
| 数值表示 | 分数类（double 存 num/den） | 不用 decimal.js/bigint：产物要单文件、体积敏感；代价是超 2⁵³ 失真（已知限制） |
| 主元选择 | `pivotFriendliness` 评分，整数优先 | 不用「第一个非零」：消元后分数爆炸，步骤也难看 |
| rankAb | 统计行最简形非零行数 | 不用 `rankA + 1` 推理式（v1.1 补丁的做法）：正确但依赖推理，按定义算更稳 |
| OCR 超时 | AbortController + 45s | 不用 `AbortSignal.timeout`（兼容性差一档） |
| API Key 存储 | `localStorage`（`scopedStorage`） | 不用 cookie：每次同源请求都会带上、4KB、iOS ITP 7 天，三项全输 |
| iOS 交付 | PWA（添加到主屏） | 不用 Capacitor 原生壳：编译必须 macOS，免费签名 7 天过期 |
| 构建清理 | 只覆盖、不递归删除 | 不做 `rm -rf dist-pages`：破坏性操作需人工确认，残留旧 hash 不影响运行 |
| 图标 | Pillow 程序化绘制 | 不用 AI 生成图：括号这种精确几何，模型画不直，缩到 48px 会歪 |

## 7. 风险与未完成事项

### 风险 1（最高）：git 仓库位置不对，直接 push 会把整个用户目录交出去

`C:\Users\hp` 下存在 `.git`（`master` 分支、零提交）。Git 会向上查找仓库，因此在项目目录里执行 `git status` 实际作用于**整个 `C:\Users\hp`**——刚才实测输出里已经出现 `Cookies/`、`.dsh/`、`.copilot/` 等目录。

**后果**：在这里 `git add .` 再 push，等于把浏览器 Cookie 目录、SSH 配置、各种工具凭据一起推到 GitHub。

**处理（按顺序）**：

1. 在项目根执行 `git init`（建自己的 `.git`，就近原则会覆盖上层）；
2. 立刻写 `.gitignore`（仓库里已有根级 `.gitignore`，确认生效：`git status` 只应看到项目文件）；
3. 确认 `git rev-parse --show-toplevel` 指向项目目录，**再** remote add / push；
4. 顺手查一下 `C:\Users\hp\.git` 是谁建的、有没有远端，没有就删掉（**删除前先 `git -C C:\Users\hp remote -v` 确认无远端、无提交**）。

### 风险 2：APK 是旧包，不包含任何修复

`线性代数计算器.apk` 仍是 v1.0。里面是另一份构建（hash 不同），要更新必须重打包，而重打包需要：

- JDK 17（Capacitor 6 要求）
- Android SDK（platform 34+ + build-tools）
- **原签名密钥**（丢了就只能换包名，用户需要卸载重装）

`source/linear-algebra-calculator/android/build-apk.sh` 是现成脚本。这一步没做，因为当前机器没有 JDK/SDK，密钥也不在手上。

### 风险 3：iOS 从未真机验证

PWA 那套是照 WebKit 文档和本地 curl 推出来的。`manifest`、`sw.js`、apple-touch-icon 都齐了，v1.5 又补了应用内引导条和 OCR 设置里的存储风险提示，但**没在 iPhone 上装过**。已知待验证点：主屏图标是否被圆角裁切（`apple-touch-icon` 生成时 `opaque=True`、不做圆角，理论上由 iOS 自己裁）、离线首开是否白屏、存储是否真的豁免 7 天清理、引导条的 `env(safe-area-inset-bottom)` 在小屏机型上会不会挡住底部操作。

### 风险 4：GitHub Actions 从未跑过

`.github/workflows/deploy-pages.yml` 写好了（push → 构建 → 48 项测试 → deploy），但仓库还没建，**一次都没执行**。首次跑最可能出问题的地方：

- `npm ci` 要求 lock 与 package.json 严格同步（脚本改动不影响，但加删依赖后要重新 `npm install` 更新 lock）；
- Pages 需要 Settings → Pages → Source 选 **GitHub Actions**，否则不发布；
- 项目站点在 `/<repo>/` 子路径，资源用相对路径（已验证），但 404 兜底页的跳转要真机确认。

### 风险 5：构建环境的三个坑（Windows）

1. **三个原生包必须一条命令装齐**。`--no-save` 装的包会被下一次任何 `npm install/uninstall` 当"多余"清掉——已加 `scripts/check-native-deps.mjs` 和 `prebuild*` 钩子，缺了会直接告诉你复制哪条命令。
2. **`fs.cpSync` 在本机静默崩溃**（退出码 127、零输出、`try/catch` 抓不到）。`make-standalone.mjs` / `make-pages.mjs` 已改成手写递归复制，**不要改回去**。
3. **路径含中文 + OneDrive**。Vite 本身没事，但脚本层容易出怪问题；换机器建议放 `D:\projects\linalg` 这类纯 ASCII 路径。
