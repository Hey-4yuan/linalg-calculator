> 目的是让新会话不必重新摸索项目结构，直接进入可动手的状态。
> 配合同目录的《交接文档》使用：提示词给"最小上下文"，交接文档给"完整背景"。
> 最后更新：2026-10-19 · 对应版本 v1.11

## 四、为什么这样写

| 做法 | 原因 |
|---|---|
| 把"不要做什么"放在前面 | 新会话最容易犯的错不是不会写代码，而是手改产物、在错的目录跑 git、装依赖时装漏。先说禁忌，省掉十几轮返工 |
| 给出确切命令而非描述 | "构建一下"会让它自己找脚本、猜参数；给命令它直接跑 |
| 写清"已经修了什么" | 否则新会话会把 L13/L4 当成待修 bug 重新"修"一遍 |
| 写清"还没做什么" | 避免它声称"已全部完成"，也避免重复做已经做过的事 |
| 强调"先读源码，不要凭产物反推" | 这个项目经历过逆向阶段，产物里的函数名是压缩的且每次构建都变 |
| 任务放最后 | 前面是稳定上下文，每次只改最后一行，好复用 |

## 五、维护

功能或版本变化后，同步改本文件里这几处，否则新会话会拿到过期信息：

1. 「现在是什么版本 / 已经修了什么」
2. 「还没做完」
3. 文档清单（新增 md 时）
4. 极简版里的原生包版本号（依赖升级后）

改完顺手跑一次：随便开个新会话粘标准版，问它"你现在认为项目状态是什么"，看回答是否与《交接文档》第 0 节一致。
