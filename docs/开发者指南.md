## 1. 仓库里有什么

```
线性代数计算器/
├── 线性代数计算器.html        # 交付产物（源码构建，勿手改）
├── 线性代数计算器.apk         # 安卓产物（旧版，按 §5 重新打包）
├── README.md / CHANGELOG.md
├── source/
│   └── linear-algebra-calculator/
│       ├── web-source/        # ★ 前端源码（Vite + React + TS）
│       │   ├── src/lib/       #   算法核心：fraction / matrix-ops / symbolic / vector-ops / ocr-service
│       │   ├── src/pages/     #   页面与 5 个功能区块
│       │   ├── src/components/#   输入网格、结果渲染、OCR 对话框
│       │   └── scripts/       #   make-standalone / make-single-file
│       ├── android/           # Capacitor 6 工程 + build-apk.sh
│       └── single-file/       # 单文件产物副本
├── tests/build-and-test.mjs   # 18 项求解器断言（直接测源码）
├── docs/                      # 全部文档 + 手册构建脚本
└── _backup/                   # 历史产物与旧补丁脚本（只读归档）
```

三条原则：

1. **只改 `source/` 里的东西**；根目录的 HTML 是产物，改了下一次构建就没了。
2. **产物由 `npm run build:all` 生成**，不要手工编辑压缩后的 JS。
3. **改完必须跑 `npm run typecheck` 与 `tests/build-and-test.mjs`**，这两步比肉眼点界面可靠。

## 2. 环境准备

| 依赖 | 版本 | 用途 |
|---|---|---|
| Node.js | 20 / 22 LTS | Vite 8 与构建脚本 |
| Python | 3.9+ | 仅用于文档构建（可选） |
| JDK 17 | — | 打 APK |
| Android SDK | platform 34 + build-tools 34 | 打 APK |

首次安装：

```bash
cd source/linear-algebra-calculator/web-source
npm install          # 约 874 个包，2–3 分钟
```

> **Windows 必看**：`package-lock.json` 是在别的平台生成的，npm 不会补装 Windows 原生二进制，构建会报
> `Cannot find module '@rolldown/binding-win32-x64-msvc'` 之类的错。一次装齐：

```bash
npm install --no-save \
  @rolldown/binding-win32-x64-msvc@1.2.7 \
  lightningcss-win32-x64-msvc@1.32.0 \
  @tailwindcss/oxide-win32-x64-msvc@4.3.3
```

⚠️ 必须**一条命令装完**——`--no-save` 装的包会在下一次 `npm install` 时被当"多余依赖"删掉。

## 3. 日常开发

```bash
cd source/linear-algebra-calculator/web-source
npm run dev          # http://localhost:5173
npm run typecheck    # tsc 类型检查
npm run lint         # typecheck + eslint
```

改代码时的落点：

| 想改什么 | 改哪里 |
|---|---|
| 算法（RREF / det / 逆 / 特征值 / 方程组） | `src/lib/matrix-ops.ts` |
| 分数精度、显示格式 | `src/lib/fraction.ts` |
| 符号运算的解析与化简 | `src/lib/symbolic.ts` |
| 向量运算 | `src/lib/vector-ops.ts` |
| OCR 提示词、请求、配置存取 | `src/lib/ocr-service.ts` |
| 单个功能区块的 UI | `src/pages/HomePage/sections/*.tsx` |
| 矩阵输入网格、单元格校验 | `src/components/MatrixGrid.tsx` |
| 结果渲染、步骤面板 | `src/components/MatrixDisplay.tsx`、`StepsAccordion.tsx` |
| 顶栏、Tab、分数开关 | `src/pages/HomePage/HomePage.tsx` |
| 主题色、字体 | `src/index.css`、`src/tailwind-theme.css` |

约定（来自 `web-source/README.md`，要遵守）：

- `src/index.tsx` 与 `src/components/ui/*` 是模板托管文件，**不要改**；
- 新页面放 `src/pages/<Name>/<Name>.tsx`，页面专属组件放同级 `components/`；
- 导入别名：`@/` → `src/`，`@shared/` → `shared/`。

## 4. 构建与产物

```bash
npm run build:all
```

等价于三步：

| 步骤 | 命令 | 产物 | 用途 |
|---|---|---|---|
| 1 | `vite build` | `dist/client/` | 平台部署（含 `routes.json`、polyfills、字体重写） |
| 2 | `node scripts/make-standalone.mjs` | `dist-standalone/` | 离线静态站；Capacitor 的 `webDir` |
| 3 | `node scripts/make-single-file.mjs` | `线性代数计算器.html` | 单文件，双击可用 |

把单文件复制到仓库根目录：

```bash
cp 线性代数计算器.html ../../../线性代数计算器.html
```

> `make-single-file.mjs` 会注入 `window.appId / userId / __BASENAME__ / _appInfo`，并做两次安全断言（CSS 里不能有 `</style>`、JS 里不能有 `</script>`）。改脚本时别破坏这两条。

**已知构建坑**：

1. 原生可选依赖缺失 → 见 §2 的一次性安装；
2. `fs.cpSync` 在本机 Windows 上会静默崩溃（退出码 127，无输出，`try/catch` 抓不到）→ `make-standalone.mjs` 已改为手写递归复制；
3. 路径含中文 / 放在 OneDrive 下 → Vite 能跑，但建议放到纯 ASCII 路径（如 `D:\projects\linalg`）。

## 5. 打 Android 包

仓库里的 `source/linear-algebra-calculator/android/` 是现成的 Capacitor 6 工程（`appId=com.doubao.linalg`，`webDir=www`），网页资源已同步为最新构建。

### 5.1 快速出 debug 包

```bash
cd source/linear-algebra-calculator/android
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/Android/Sdk
./build-apk.sh
# 产物：android/app/build/outputs/apk/debug/app-debug.apk
```

脚本做三件事：`npm install` → 写 `local.properties` 并 `npx cap sync android` → `./gradlew assembleDebug`。

### 5.2 只更新网页资源

```bash
# 用最新 dist-standalone 覆盖 www（cap sync 会再同步到 app/src/main/assets/public）
cp -r web-source/dist-standalone/* ../linear-algebra-calculator/android/www/
cd ../linear-algebra-calculator/android && npx cap sync android
```

`.map` 文件不要带进 APK（体积白涨约 4 MB）。

### 5.3 出正式包

Android Studio 打开 `android/android/`，`Build → Generate Signed APK` 用你的 keystore 签名；或命令行：

```bash
cd android/android
./gradlew assembleRelease
$ANDROID_HOME/build-tools/34.0.0/apksigner sign --ks my.jks \
  --out app-release-signed.apk app/build/outputs/apk/release/app-release-unsigned.apk
```

注意：

- **签名密钥丢失 = 无法给已安装用户推送更新**，务必备份；
- 包名 `com.doubao.linalg` 不要改，否则手机会装成两个应用；
- 仓库根目录的 APK 是旧构建，未包含 v1.2 的修复，需按本节重打。

## 7. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `Cannot find module …win32-x64-msvc` | 原生可选依赖缺失 | §2 的一次性安装 |
| `build:all` 只出了 dist 就停 | `make-standalone.mjs` 里 `fs.cpSync` 崩了 | 确认脚本是手写 `copyDir` 版本（已修） |
| 白屏 | 产物被手改坏，或 `#root` 缺失 | 重新 `build:all`；不要手改 bundle |
| 点识别没反应 | 未配置 OCR（按钮显示「配置 OCR」） | 卡片标题右侧按钮 → 填三项 → 保存 |
| 识别报 401/403 | Key 错或过期 | 重填；确认 Base URL 带 `/v1` |
| 识别报 404 | Base URL 多写/少写路径 | 只填到版本号，如 `https://api.openai.com/v1` |
| 识别超时 | 45 秒无响应（v1.2 起有明确提示） | 换网络/换中转；模型不支持图像时也会慢 |
| 刷新后配置丢失 | 隐私模式禁用 localStorage；或换了源（`file://` 与 `localhost` 是不同的库） | 允许本地存储；固定同一种打开方式 |
| APK 覆盖安装失败 | 签名不一致 | 卸载旧版再装，或使用同一 keystore |

## 8. 附录：没有源码时的应急手段

（现在用不上，保留给"只拿到产物"的场景。）

1. **把 `\uXXXX` 还原成明文再搜**：

   ```python
   import re
   src = open("线性代数计算器.html", encoding="utf-8").read()
   dst = re.sub(r"\\u([0-9a-fA-F]{4})", lambda m: chr(int(m.group(1), 16)), src)
   open("_debug/unescaped.js", "w", encoding="utf-8", errors="backslashreplace").write(dst)
   ```

   `errors="backslashreplace"` 不能省：bundle 里有孤立代理对（emoji 被截断）。

2. **按中文文案定位**（不要依赖压缩函数名，每次构建都变）：`单矩阵运算`、`符号行列式最多支持 3 阶矩阵`、`高斯消元过程`、`/chat/completions`、`__app_linalg_ocr_config`。

3. **改产物必须字节级**：用 `read_bytes` / `write_bytes`，不要用文本模式——文本模式会把 LF 全转成 CRLF，文件凭空多出上百字节。

4. **改完做三件事**：抽出的脚本 `node --check`、断言补丁片段唯一命中、浏览器实测。

## 9. 文档维护

Markdown 是唯一事实来源，HTML 手册由脚本生成：

```bash
pip install markdown
python docs/build_docs.py     # → docs/手册.html
```

改文档的约定：

- 界面文案、报错文案必须与源码逐字一致；
- 算法描述与代码冲突时以源码为准，并同步修订；
- 新增功能同时更新：README 能力表、用户手册对应章节、技术手册算法节、测试手册用例；
- **不要再新增"按压缩产物反推"的结论**——源码在手，直接读。
