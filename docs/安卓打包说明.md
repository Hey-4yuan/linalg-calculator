# 线性代数计算器 · 安卓 APK 打包说明

> 版本 **v1.9** · 包名 `com.doubao.linalg` · versionCode **6** / versionName **1.9**
> 这份材料是自包含的：网页资源已经同步进安卓工程的 `assets/public`，**不需要 Node.js、不需要联网装 npm 包**，只需要 JDK + Android SDK。

---

## 一、机器要求

| 项目 | 要求 | 备注 |
|---|---|---|
| 系统 | Windows 10/11 x64（Linux 见第六节） | |
| JDK | **17**（LTS） | ⚠️ **不要用 21**：本工程用的 Gradle 8.2.1 不支持，会报 `Unsupported class file major version 65` |
| Android SDK | `platform-tools` + `platforms;android-34` + `build-tools;34.0.0` | 通过 Android Studio 的 SDK Manager 勾选安装最省事 |
| 磁盘 | ≥ 3 GB 空闲 | Gradle 发行版 + 依赖首次下载约 300 MB |
| 网络 | 能访问 `services.gradle.org`、`maven.google.com`、`repo.maven.apache.org` | 首次构建必须联网，之后可离线 |

> 环境变量只需要两个：`JAVA_HOME` 指向 JDK 17 根目录；`ANDROID_HOME` 指向 SDK 根目录。
> 解压路径**建议用纯英文**，例如 `C:\build\linalg`（中文路径偶发资源编译失败）。

## 三、快速路径：出一个能装的 APK（3 步）

### 第 1 步：设置两个环境变量

在 cmd 里执行（路径换成你自己的）：

```bat
setx JAVA_HOME "C:\Program Files\Java\jdk-17"
setx ANDROID_HOME "%LOCALAPPDATA%\Android\Sdk"
```

**设完要新开一个 cmd 窗口**才生效。验证：

```bat
"%JAVA_HOME%\bin\java" -version      :: 应显示 17.x
dir "%ANDROID_HOME%\platforms"       :: 应能看到 android-34
```

### 第 2 步：打包

双击 `build-apk.bat`，或在 cmd 里：

```bat
cd /d C:\build\linalg\线性代数计算器-安卓打包-v1.9
build-apk.bat
```

脚本会打印 JDK/SDK 检查结果，然后执行 `gradlew assembleDebug`。首次约 **5–15 分钟**（下载依赖），之后 1–2 分钟。

### 第 3 步：取产物

```
android\app\build\outputs\apk\debug\app-debug.apk
```

这个 APK **可以直接安装、可以直接发给别人**（debug 签名，安卓允许安装；只是不能上架应用商店）。

## 四、正式路径：用自己的签名密钥出 release 包

debug 包能用，但每次构建签名都可能变，且不能上架。想正式分发就自己生成一个密钥。

### 1) 生成密钥（只做一次，**务必单独备份**）

```bat
keytool -genkeypair -v -keystore linalg-release.jks -alias linalg ^
  -keyalg RSA -keysize 2048 -validity 10000
```

会问你密码、姓名、组织等，随便填；**密码和 .jks 文件丢了，以后就再也无法给这个应用发升级包**。

### 2) 构建签名包（不用改任何配置文件）

```bat
cd android
gradlew.bat assembleRelease --no-daemon --console=plain ^
  -Pandroid.injected.signing.store.file=C:\build\linalg-release.jks ^
  -Pandroid.injected.signing.store.password=你的密码 ^
  -Pandroid.injected.signing.key.alias=linalg ^
  -Pandroid.injected.signing.key.password=你的密码
```

产物：`android\app\build\outputs\apk\release\app-release.apk`

### 3) ⚠️ 关于"能不能覆盖升级"

- 原来那版 **v1.0 的签名密钥不在手上**（当时打包用的环境和密钥没有留存）。
- 用新密钥打出来的包，**包名相同但签名不同** → 老用户**无法覆盖安装，必须先卸载**。
- 如果不想让人卸载：把包名改成 `com.doubao.linalg.v2`（改 `android/app/build.gradle` 里的 `applicationId` 和 `namespace`，并同步改 `capacitor.config.json` 的 `appId`），新旧版可以并存。

## 五、装到手机后怎么验（8 项，2 分钟）

| # | 操作 | 期望 |
|---|---|---|
| 1 | 安装并打开 | 显示「线性代数计算器」，无白屏、无闪退 |
| 2 | 单矩阵运算 → 示例填充 → 行列式 det | 立刻出结果，且有「消元过程」步骤面板 |
| 3 | 顶栏切到「分数模式」 | 结果显示 `1/3` 这类分数，不是小数 |
| 4 | 结果卡右上角点「复制」 | 提示已复制；粘到微信/记事本能看到数字 |
| 5 | 配置 OCR → 填 Base URL / Key / 模型 → 上传一张含**四阶/五阶行列式**的图 | 网格行列数必须与图片一致（5 阶就是 5×5）；裁剪框默认整张图。此项需要真实 API Key，没 Key 就跳过，不影响打包 |
| 6 | 关掉流量和 WiFi，重开 App | 仍能打开并做本地计算（OCR 除外） |
| 7 | 设置 → 应用 → 线性代数计算器 | 版本显示 **1.5**，权限只有「网络」 |
| 8 | 横屏 / 小屏手机 | 布局不溢出，按钮不重叠 |

## 六、Linux / macOS 打包（如果云电脑是 Linux）

```bash
export JAVA_HOME=/path/to/jdk-17

chmod +x build-apk.sh
./build-apk.sh
```

`build-apk.sh` 会先检查环境变量，然后直接进 `android/` 跑 `./gradlew assembleDebug`。

## 七、常见报错对照

| 报错 | 原因 | 处理 |
|---|---|---|
| `Unsupported class file major version 65` | 用了 JDK 21 | 装 JDK 17，把 `JAVA_HOME` 指过去，新开窗口 |
| `SDK location not found` | 没设 `ANDROID_HOME` | 见第三节第 1 步 |
| `Failed to install the following Android SDK packages` | 缺 platform 34 / build-tools | SDK Manager 里补装 |
| `Could not resolve com.android.tools.build:gradle` | 网络不通（首次要联网） | 换网络或配代理后重试 |
| `processDebugResources` 失败 + 路径里有中文 | 中文路径 | 解压到纯英文目录重试 |
| `Execution failed for task ':capacitor-android:compileDebugJavaWithJavac'` | `node_modules/@capacitor/android` 缺失 | 确认该目录存在（本包已内置，别删） |
| 构建成功但 App 白屏 | `assets/public` 没内容 | 确认 `android/app/src/main/assets/public/index.html` 存在 |

## 八、如果要更新网页内容（v1.9 之后又改了代码）

本包里的网页资源已经是最新的 v1.9，**正常情况下不需要动**。真要更新时二选一：

**方式 A（不需要 Node）**：把新构建出的 `dist-standalone/` 里所有文件覆盖到 `www/`，再同样覆盖到 `android/app/src/main/assets/public/`，然后重新打包。

**方式 B（有 Node 18+）**：

```bash
npm install
npx cap sync android
cd android && ./gradlew assembleDebug
```
