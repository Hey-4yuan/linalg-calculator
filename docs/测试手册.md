用途：验收新版本、回归改动、给算法层补自动化测试时提供**可判定**的用例。
每个用例给出「输入 → 期望输出」，期望值均已独立核算（非从程序反推）。

## 1. 测试范围与环境

| 项 | 内容 |
|---|---|
| 被测对象 | `线性代数计算器.html`（桌面 Chrome/Edge）、`线性代数计算器.apk`（Android WebView） |
| 测试类型 | 手工功能测试为主；方程组求解器有可复跑的自动回归（附录 A）；其余算法用独立实现交叉核对（附录 B） |
| 不做 | 安全渗透、并发、多用户（无后端、无账号） |
| 环境矩阵 | 桌面 Chrome 最新版 / Edge 最新版 / 手机 Chrome；窗口宽度 375px、768px、1440px 三档 |

**判定原则**

- 数值类：分数模式下必须**完全相等**；小数模式下允许最后一位舍入差（≤1e-6）。
- 文本类：报错文案与《用户手册》第 9 节逐字一致（文案是用户可感知的行为）。
- 布局类：无横向溢出、按钮不重叠、结果不被裁切。

| SM-06 | P1 | `1 1 / 0 1` | 幂 Aⁿ=5 | `1 5 / 0 1` |
| SM-07 | P1 | `1 1 / 0 1` | 幂 Aⁿ=0 | 单位阵 `1 0 / 0 1` |

| SM-11 | P1 | `4 1 / 2 3` | 特征值/向量 | 特征值 `5`、`2`；对应特征向量方向约 `(1,1)`、`(1,-2)`（归一化后约为 ±(0.7071, 0.7071) 与 ±(0.4472, −0.8944)，正负号由迭代初值决定） |
| SM-12 | P1 | `0 -1 / 1 0` | 特征值 | 识别为**复特征值** `0 ± 1i`（实部 0、虚部 ±1），不输出实数特征值列表 |
| SM-13 | P1 | `2 0 0 / 0 3 0 / 0 0 5` | 特征值 | `5, 3, 2`（降序）；特征向量近似为三个坐标轴方向 |

| SM-15 | P1 | `1 2 3 / 4 5 6` | 转置 | `1 4 / 2 5 / 3 6`（3×2） |
| SM-16 | P2 | 10×10 单位阵 | det / 逆 / rank | `1` / 单位阵 / `10` |
| SM-17 | P2 | `1/2 0 0 / 0 1/3 0 / 0 0 1/5` | 行列式（分数模式） | `1/30`；小数模式 `0.033333` |
| SM-18 | P2 | 3×3 矩阵 | 行列式 → 展开「计算步骤」 | 每步形如 `R3 ← R3 − 2R1`，末步矩阵为上三角，与 det 值自洽 |

## 4. 线性方程组用例

### 4.1 三种结论

| 编号 | 级别 | 增广矩阵 | 期望 |
|---|---|---|---|
| EQ-01 | P0 | `2 1 -1 ∣ 8`、`-3 -1 2 ∣ -11`、`-2 1 2 ∣ -3` | **唯一解**：x1=2，x2=3，x3=−1；附「系数矩阵秩 = 增广矩阵秩 = 3 = 未知数个数 3」 |
| EQ-02 | P1 | `2 3 ∣ 7`、`1 -1 ∣ 1` | **唯一解**：x1=2，x2=1 |
| EQ-03 | P0 | `1 2 3 ∣ 1`、`2 4 6 ∣ 2`、`3 6 9 ∣ 3` | **无穷多解**：自由变量 x2、x3；特解 (1,0,0)；η₁=(−2,1,0)，η₂=(−3,0,1) |
| EQ-04 | P0 | `1 1 ∣ 1`、`2 2 ∣ 3` | **无解**：出现「方程组存在矛盾方程，没有解。」；附注显示「系数矩阵秩 = 1，增广矩阵秩 = 2，秩不相等故无解」（v1.1 起两个数不再相同） |
| EQ-05 | P2 | `1 1 ∣ 0`、`2 2 ∣ 0`（齐次） | **无穷多解**：自由变量 x2；特解 (0,0)；η₁=(−1,1) |
| EQ-06 | P1 | 任意矩阵 | 点「求解」前 | 结果区显示「点击「求解」查看结果」 |
| EQ-07 | P1 | 任意有解的方程组 | 展开「高斯消元过程」 | 每步行变换后矩阵与 det/RREF 记录一致，常数列前有竖线 |

> **EQ-04 记录**：旧版（v1.0）会打印「系数矩阵秩 = 1，增广矩阵秩 = 1，秩不相等故无解」，两个数字相等，属缺陷 L13。v1.2 起由源码修复，应显示 1 与 2；若仍看到 `1 与 1`，说明用的是旧产物。

### 4.2 尺寸与录入

| 编号 | 级别 | 操作 | 期望 |
|---|---|---|---|
| EQ-08 | P1 | 方程数 +/− | 行数 1–10 变化，超出范围按钮禁用 |
| EQ-09 | P1 | 未知数 + | 列数 = 未知数 + 1，`b` 列始终在最后，原有数据保留在左侧 |
| EQ-10 | P1 | 点「唯一解」「无穷多解」「无解」「示例」 | 分别载入对应示例并清空旧结果，弹出「已加载…示例」提示 |
| EQ-11 | P2 | 增广矩阵识别（OCR） | 识别后列数 = 原图列数，常数列在最后 |

## 5. 向量运算用例

v=(1,2,3)，w=(4,5,6)

| 编号 | 级别 | 操作 | 期望 |
|---|---|---|---|
| VEC-01 | P0 | 点积 | `32` |
| VEC-02 | P0 | 叉积 | `(-3, 6, -3)` |
| VEC-03 | P1 | 长度/模 | ‖v‖≈`3.741657`，‖w‖≈`8.774964` |
| VEC-04 | P1 | 单位化 | v̂≈(0.267261, 0.534522, 0.801784)，ŵ≈(0.455842, 0.569803, 0.683763) |
| VEC-05 | P1 | 夹角 | `0.225726 rad` / `12.9332°` |
| VEC-06 | P1 | 线性组合，系数 α=2、β=−1/2 | `(0, 1.5, 3)`；标题显示 `线性组合 2·v + -1/2·w` |
| VEC-07 | P1 | 维度调到 2 | 叉积按钮禁用，悬停提示「仅三维向量可用」 |
| VEC-08 | P1 | 把 v 设为 (0,0,0) | 单位化报「零向量不能单位化」；夹角报「零向量无法计算夹角」 |
| VEC-09 | P2 | 维度调到 5，v=(1,1,1,1,1) w=(1,1,1,1,1) | 点积 `5`；夹角 `0 rad`；模 ≈2.236068 |
| VEC-10 | P2 | 维度 2→5→2 往返 | 已填分量保留，缺位补 0，结果区清空 |

> 说明：两个向量的维度由**同一个**维度控件控制，因此「点积要求向量维度相同」这条错误在实际 UI 中不可达（属防御性代码）。

|---|---|---|---|---|

| SY-03 | P1 | `a b c / d e f / g h i` | 行列式 | `a*(e*i - f*h) - b*(d*i - f*g) + c*(d*h - e*g)` 的等价形式 |

| SY-05 | P1 | 4×4 字母矩阵 | 逆矩阵 | 报错「符号逆矩阵最多支持 3 阶矩阵」 |
| SY-06 | P1 | 4×4 字母矩阵 | RREF | 正常出结果（≤4×4） |
| SY-07 | P1 | 5×5 字母矩阵 | RREF | 报错「符号行最简形最多支持 4×4 矩阵」 |
| SY-08 | P1 | `a b / c d` | 迹 | `a + d` |
| SY-09 | P2 | `pi 0 / 0 1` | 行列式 | 结果含 `pi` |
| SY-10 | P1 | `a+` | 计算 | 报错（「表达式意外结束」类） |
| SY-11 | P1 | `(a+b` | 计算 | 报错（「缺少右括号」类） |
| SY-12 | P1 | `a$` | 计算 | 报错「无法识别字符: $」 |
| SY-13 | P2 | `2*a+3`、`x^2`、`a/b` | 计算（任一带该格的行列式） | 正常解析，结果保留结构 |
| SY-14 | P2 | `2a`（不写乘号） | 计算 | 被当作一个变量名（已知行为，不是 Bug）；文档已说明需写 `2*a` |
| SY-15 | P1 | 点「示例」「单位阵」「清零」 | — | 载入 a..i 示例 / 生成单位阵（仅方阵可点）/ 全 0 |

## 7. OCR 用例

前置：准备一张清晰的 3×3 手写/打印矩阵截图；一个可用的 OpenAI 兼容视觉模型 Key。

| 编号 | 级别 | 场景 | 期望 |
|---|---|---|---|
| OCR-01 | P0 | 全新浏览器，未配置 | 各矩阵卡片标题右侧的按钮显示「配置 OCR」；点开弹窗，默认 Base URL `https://api.openai.com/v1`、模型 `gpt-4o-mini`、Key 为空 |
| OCR-02 | P0 | 保存时留空任一项 | 依次提示「请输入 Base URL」「请输入 API Key」「请输入模型名」 |
| OCR-03 | P0 | 三项填好后保存 | 提示「配置已保存」；卡片上的按钮变为上传入口，悬停提示「上传图片识别矩阵」 |
| OCR-04 | P1 | 刷新页面 | 配置仍在（读 `localStorage`），无需重填 |
| OCR-05 | P1 | 点「清除配置」 | 提示「配置已清除」；卡片按钮回到「配置 OCR」；Key 输入框清空 |
| OCR-06 | P0 | 上传清晰 3×3 图片 | 矩阵被正确回填；提示「识别成功」；右上角维度显示 `3×3` |
| OCR-07 | P1 | 上传含 1 处涂鸦的图片 | 提示「有 N 个单元格识别失败，已置为 0，请核对」；N≥1；其余格子正确 |
| OCR-08 | P1 | Key 填错（如 `sk-invalid`） | 报错含状态码，如「API 请求失败 (401): …」；原有矩阵不被清空 |
| OCR-09 | P1 | Base URL 漏 `/v1` 或多写路径 | 报错含 404 或 JSON 解析错误，提示中保留原始响应片段 |
| OCR-10 | P1 | 断网后点识别 | 报错「识别失败：网络错误或 API 调用异常」 |
| OCR-11 | P1 | 图片编辑：左转→右转→水平翻转→垂直翻转→重置 | 预览方向逐步变化，重置后回到初始；确认后回填的矩阵方向与预览一致 |
| OCR-12 | P1 | 拖裁剪框只留矩阵区域 | 裁剪生效，上传的图片内容为裁剪后的区域（Network 面板可见 dataURL 变化） |
| OCR-13 | P2 | 方程组模块识别 | 图片为增广矩阵时，回填后列数含常数列，`b` 在最后 |
| OCR-14 | P2 | 符号矩阵识别 | 字母与 π 被识别为可解析表达式（回填后计算不报「无效数值」） |
| OCR-15 | P2 | 超大图片（>5 MB） | 允许上传；请求体明显变大但能返回（无尺寸保护，属已知限制） |
| OCR-16 | P2 | Base URL 填一个只吞请求不回包的地址（如 `http://10.255.255.1/v1`） | **约 45 秒**后结束等待，提示「识别超时（45 秒无响应），请检查网络或更换模型接口」（v1.2 源码） |

## 附录 B：用 Python 交叉核对期望值

自动化校验的核心是用独立实现复算，避免「从程序输出反推期望值」。

```python
from fractions import Fraction as F

def rref(M):
    M = [[F(x) for x in r] for r in M]
    rows, cols, r, piv = len(M), len(M[0]), 0, []
    for c in range(cols):
        p = next((k for k in range(r, rows) if M[k][c] != 0), None)
        if p is None: continue
        M[r], M[p] = M[p], M[r]
        pv = M[r][c]
        M[r] = [x / pv for x in M[r]]
        for k in range(rows):
            if k != r and M[k][c] != 0:
                f = M[k][c]
                M[k] = [a - f * b for a, b in zip(M[k], M[r])]
        piv.append(c); r += 1
        if r == rows: break
    return M, piv

print(rref([[1,2,3],[4,5,6],[7,8,9]]))
# 期望: [[1,0,-1],[0,1,2],[0,0,0]], 主元列 [0,1]
```
