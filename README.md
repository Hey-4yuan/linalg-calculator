# 线性代数计算器

一个纯前端、可离线使用的线性代数计算器，支持**精确分数运算**的矩阵计算、线性方程组求解、向量运算、符号矩阵运算，以及基于视觉大模型的**图片识别录入**。

计算全部在浏览器本地完成，不依赖后端；唯一的外发请求是用户在设置中自行配置的 OCR 大模型接口。

**源码已归档到 `source/`**，所有产物都由源码构建，可以本地改、本地出包。

## 二、使用须知（请先读）

**① 计算结果可信，图片识别的结果不可全信。**

矩阵运算、方程组、向量、符号运算走的是精确分数（不是浮点），结果可以直接用。
但**图片识别是另一回事**：它是把图片交给第三方视觉大模型去"看数字"，模型会犯人类眼睛不会犯的错。

| 常见识别错误 | 长什么样 |
|---|---|
| 漏读整行/整列 | 5×5 只读出 4×5，或把最外圈切掉 |
| 单个数字读错 | `7` 认成 `1`、`0` 认成 `6`、`2` 认成 `Z` |
| 负号、小数点丢失 | `-3` 变 `3`，`0.5` 变 `5` |
| 符号矩阵认错 | `α` 与 `a`、`β` 与 `B` 混淆 |
| 分数拆错 | `1/2` 读成 `12` 或 `1` 和 `2` 两个格子 |

**所以：识别结果填进网格后，请逐格核对原图，确认无误再点计算。**
App 会做一层兜底——对"图上有墨迹但被读成 0"的格子给黄色提示，但那只是启发式检查，**挡不住读成别的数字**，不能代替你自己看一遍。

**② 识别失败不要反复重试。**
同一个模型对同一张图往往稳定地错（重跑四次结果一模一样是常态）。换模型、换张更正的图、或者手动输入，比死磕更快。

**③ 你的 API Key 只存在你自己的设备上。**
配置写在浏览器 `localStorage`（APK 版是 WebView 的本地存储），不会上传到任何服务器，也不经过本项目的作者。
但反过来说：**清除浏览器数据、换设备、或者 iOS Safari 标签页超过 7 天未使用，配置就会丢**，需要重新填。
（iOS 上「添加到主屏幕」可以避开这条清理策略，App 会主动提示你加。）

**④ 本项目不对使用结果负责。**
作业、考试、工程计算请自行复核。识别错误导致的任何后果，作者不承担责任。

## 四、功能总览

| 模块 | 能力 | 规模上限 | 精度策略 |
|---|---|---|---|
| 单矩阵运算 | 行列式 det、逆矩阵、秩 rank、转置 Aᵀ、行最简形 RREF、特征值/特征向量、迹 tr、幂 Aⁿ | 10×10；特征值 ≤ 5 阶 | det/逆/RREF/幂 为**精确分数**；特征值为数值近似 |
| 双矩阵运算 | A + B、A − B、A × B | 10×10 | 精确分数 |
| 符号运算 | 含字母与 π 的矩阵：det、inv、rank、transpose、RREF、trace | 6×6（det/inv ≤ 3 阶，RREF ≤ 4×4） | 符号表达式精确化简 |
| 线性方程组 | 增广矩阵输入 → 唯一解 / 无穷多解（自由变量 + 基础解系）/ 无解，附高斯消元步骤 | 10 行 × (1–10 未知数 + 1) | 精确分数 |
| 向量运算 | 点积、叉积（仅 3 维）、模、单位化、夹角（rad + °）、线性组合 | 2–5 维 | 点积/组合为精确分数，模与夹角为浮点 |
| 图片识别 | 拍照/选图 → 裁剪旋转翻转 → 视觉模型识别；三种模式（数值矩阵 / 符号矩阵 / 增广矩阵）；支持行列式（`|…|`）与一图多题（识别后选择载入） | 由模型与提示词约束 | 识别失败单元格置 0 并提示核对；尺寸以图片实际行列数为准 |

顶栏右侧的开关（标签在**「小数模式」/「分数模式」**之间切换）决定所有结果的呈现方式：小数模式显示 6 位小数（自动去尾零），分数模式显示 `p/q`。开关状态随浏览器本地保存。

每张结果卡右上角有**「复制」**：复制成制表符分列的纯文本，粘到 Excel / WPS 表格会自动分格。

**iPhone / iPad**：部署到 HTTPS 后建议先「分享 → 添加到主屏幕」再用。Safari 标签页里的本地数据（含 OCR 的 API Key）在 7 个「使用日」无交互后会被系统清理，主屏幕 Web App 使用独立存储，不受这条规则影响。应用内会主动弹提示。

## 五、快速开始

**Web 版**：双击 `线性代数计算器.html` → 直接可用。首次打开无需联网（字体走系统回退），OCR 功能需先配置。

**APK 版**：安装 `线性代数计算器-v1.12.apk` → 打开即用（仅申请网络权限，用于 OCR）。

**配 OCR（两版通用）**：在任意矩阵卡片标题右侧点「配置 OCR」→ 填 `Base URL`、`API Key`、`视觉模型名` → 保存。要求接口兼容 OpenAI Chat Completions 协议且支持图像输入。以 DeepSeek 中转为例：

```
Base URL: https://api.deepseek.com
视觉模型名: deepseek-flash
API Key:  自行申请（见附图手册）
```

保存后按钮变成「图片识别」，旁边多一个齿轮「OCR 设置」。

> API Key 以明文保存在浏览器 `localStorage`，不会上传到任何第三方；换设备或清缓存后需重新填写。**不要使用他人共享的 Key，也不要把自己的 Key 发给别人。** 存储边界与加固方案见 [docs/可行性-视觉模型配置存储.md](docs/可行性-视觉模型配置存储.md)。

## 八、必须知道的三条限制

1. **矩阵数值全部走 JS 的 `number`**（`Fraction` 内部是 `num/den` 两个 double）。元素绝对值超过 `2^53` 或分数分子分母累乘过大时会出现精度漂移，此时结果不再严格精确。
2. **n ≥ 3 的特征值用 QR 迭代近似**（100 次 / 容差 1e-10），只保证实特征值收敛；复特征值仅在 2×2 时专门处理；阶数上限 5。
3. **产物不要手改**。压缩后的 bundle 可读性差，改了下次构建就丢；改 `source/` 再 `npm run build:all`。
